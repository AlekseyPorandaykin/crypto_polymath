# Алгоритм работы

## Свечи и первичные индикаторы

1. Загружаем свечи в зависимости от интервала и глубины
2. Создаём событие, что загрузили свечи определённых параметров (свечей очень много по каждой паре — только сигнал, без тела)
3. Обрабатываем событие загрузки свечей (`LoadedCandlesticksForSymbolAction`)
4. Рассчитываем candle indicators (Heiken Ashi) и первичные индикаторы (`indicator.CalcIndicators`)
5. Публикуем `CreatedIndicatorEvent` в очередь `indicators`

## Вторичная аналитика

6. Calculator читает очередь `indicators`, группирует по `exchange/symbol/unit/interval`
7. Для каждого индикатора вызывается `analysis.CalculateByIndicator` (RSI, MACD Main Line, TrendByEMA, …)
8. Публикуем `CreatedAnalyticEvent` в очередь `analytics`

## Производная аналитика (оптимизированный путь)

9. `listenAnalytic` читает пачку из очереди `analytics`
10. Сообщения группируются по `{exchange, symbol, unit, interval}` и сортируются по `Datetime`
11. **Один вызов** `handleAnalytic` → `CalculateByAnalytics` на всю группу
12. Внутри `CalculateByAnalytics`:
    - группировка по `Name` исходной аналитики (например, `MACDMainLine`);
    - для каждого `CalculatorByAnalytic` и поддерживаемого `depth` — `OscillatorByAnalytics`;
    - один `FindMany` в storage на все `datetime` батча;
    - расчёт и `Save` только для отсутствующих записей
13. Результаты диспатчатся как новые `CreatedAnalyticEvent` (MACD Signal Line → MACD Histogram)

### Сравнение подходов

| Подход | Запросов в БД на 100 событий | Примечание |
|--------|------------------------------|------------|
| По одному (`CalculateByAnalytic` в цикле) | ~100 `FindManyByIndicator` | Старый паттерн |
| Пакетный (`CalculateByAnalytics`) | ~2–4 `FindMany` | Текущая реализация в Calculator |

MACD Signal Line: `SupportDepth(1)` — не запускать расчёт для depth 8, 9, 10, … из конфига (результат всегда с `depth = 1`).
