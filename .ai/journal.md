# Change journal

What changed, and why. Newest entry first, so that reading the top of this file tells you
the current state of the project.

This is not a duplicate of `git log`. A commit says which lines moved; an entry here says
which decision was taken, what was rejected and what is still open — the things that are
expensive to reconstruct from a diff later.

## How to write an entry

Append one entry when a task is finished, before reporting back. Copy the template, keep it
short, and skip a field rather than filling it with nothing.

```markdown
## YYYY-MM-DD — Short title

**Task.** What was asked for, in one or two sentences.
**Why.** The reason the change was needed, if it is not obvious from the task.
**Changed.** Areas and key files.
**Decisions.** Choices made and options rejected, with the reason.
**Checks.** Commands run and their outcome.
**Left open.** Known gaps, follow-ups, things deliberately not done.
```

Rules for entries:

- Record decisions, not keystrokes. "Kept the landing page static except for one module,
  because crawlers do not run JavaScript" is worth an entry; "renamed a variable" is not.
- If you discovered something about the codebase that cost you time — a hanging test suite,
  stale generated code, a surprising invariant — write it down. That is the part nobody can
  recover from the diff.
- When a decision was the user's, say so. It stops the next assistant from re-litigating it.

## 2026-07-31 — AI context folder

Codex and Claude Code all read, and start a journal of changes.

`conventions.md`, `journal.md`); entry points `AGENTS.md`, `CLAUDE.md` and

**Decisions.** One folder with per-tool pointers rather than a rules file per tool: the

but not reasons. Context files are in English, while Go comments stay Russian.

`conventions.md` so that Codex and Claude see it too; the Cursor rule now points there.

`./internal/ui/api/v1/impl/` — green. Every path referenced from `.ai/` was verified to
exist.

`docs/overview.md`; nobody has reconciled them.

## 2026-07-31 — Contact form on the landing page

**Task.** A "Contact us" button on the landing page opening a dialog with sender email,
subject, message and Send/Cancel; a REST endpoint receiving it, with no delivery yet.
**Changed.** `POST /contact` in the contract plus regenerated `spec` package; new
`internal/ui/api/v1/impl/contact_handler.go`; dialog markup in `static/index.html`, new
`static/js/contact.js`, styles in `static/css/app.css`; tests in `spec_test.go`,
`pages_test.go`, `contact_handler_test.go`; a note in `llms.txt`.
**Decisions.** The endpoint validates the message, logs it through zap and answers `202` —
the user chose this over `501` or a silent stub, so nothing is lost while delivery is
missing. `202` rather than `200` on purpose: accepted for delivery is not the same as
handled. The landing page gained its first script; the "no scripts" test was relaxed to
"exactly one script, the contact module", and a `noscript` block swaps the button for a
`mailto:` link so scripting-off visitors are not left with a dead button. Field limits are
duplicated from the contract into the form deliberately, and a test compares them.
**Checks.** Full test run plus BDD green. Success, rejection and scripting-disabled paths
verified in headless Chrome.
**Left open.** No mail delivery — messages exist only in the log. `X-Token` skips the rate
limiter entirely and the token is not validated, so the form can be flooded by sending any
token string; needs solving before real delivery. The `mailto:` fallback uses the address
from the contract's `contact` section.

## 2026-07-31 — Site and contract switched to English

**Task.** Translate the whole site to English, tune SEO for an international audience
including AI crawlers, and make every text — comments included — English in
`api/rest/v1/openapi.yaml` and `internal/ui/web/static`.
**Changed.** All three pages, every UI string in `static/js/**`, `llms.txt`, the crawler
list in `pages.go`, `domain.IndicatorDescriptions`, all contract descriptions and YAML
comments.
**Decisions.** Go code and tests stay commented in Russian; only externally readable text
went English. Number formatting follows `en-US` and dates `en-GB` with a spelled-out month,
because a numeric date would be misread by half the audience either way. Three tests now
enforce the split (`TestStaticFilesAreEnglish`, `TestContractIsEnglish`,
`TestIndicatorDescriptionsAreEnglish`), each scanning for Cyrillic characters.
**Checks.** Full test run plus BDD green; pages re-checked in headless Chrome at desktop
and mobile widths.
**Left open.** The contract still advertises the production server as
`http://www.cryptopolymath.org/api/v1` while the canonical site is
`https://cryptopolymath.org` — left alone because changing it affects generated clients and
deployment.
